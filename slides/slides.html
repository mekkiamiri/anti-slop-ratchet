Le ratchet
  • Une remarque revient deux fois en revue
  • L'agent écrit la règle, et son test
  • Branchée dans la boucle de l'agent et dans la CI

Démo · 3 / 7 · la règle
noClasses().should()
    .callConstructor(BigDecimal.class, double.class)
    .orShould().callConstructor(BigDecimal.class, double.class, MathContext.class)

    .because("revue : « … Pour de l'argent : new BigDecimal(\"0.1\") … »");

Démo · 6 / 7 · dans la boucle de l'agent
// .claude/settings.json
"PostToolUse": [{ "matcher": "Edit|Write",
  "hooks": [{ "type": "command", "timeout": 180,
    "command": ".../archunit-gate.sh" }] }],
"Stop": [{ "hooks": [ /* même script */ ] }]

Java modifié → mvn -q test -Dtest='*ArchTest' → exit 2

{{CHROME}}
Format vérifié sur la doc officielle des hooks Claude Code. PostToolUse exit 2 : Claude lit stderr. Stop exit 2 : Claude ne peut pas rendre la main. Au Stop, le script revérifie à chaque fois ; Claude Code plafonne à 8 relances, ensuite c'est la CI qui bloque. Le script distingue « règle cassée » et « build cassé », et ne relance pas Maven si le Java n'a pas changé.
