Départ · ce que vous avez aujourd'hui

Vous avez mis votre agent de code dans un harnais : tests, linters et règles qui bloquent tant que c'est rouge.

  • Des tests et des linters (PMD, SpotBugs, Checkstyle)
  • Des règles d'architecture (ArchUnit) : moi, 11 remarques de revue devenues 11 règles
  • Un hook relance tout après chaque fichier : l'agent ne rend la main que si c'est vert

Harnais = tout ce qui entoure l'agent pour vérifier son code (mot de Birgitta Böckeler)

{{CHROME}}
Harnais, c'est le mot de Birgitta Böckeler : tout ce qu'on met autour de l'agent, des consignes avant, des capteurs après. Mon harnais : 11 remarques de revue qui revenaient (pas de new BigDecimal(0.9) pour de l'argent, pas de java.util.Date…) devenues 11 règles ArchUnit, plus un hook, un script branché sur l'agent, qui les relance après chaque fichier écrit. Tant qu'une règle casse, l'agent ne peut pas finir. Détail dans RATCHET.md. Transition : j'ai branché ça, et j'ai compté.

Problème · Birgitta Böckeler · martinfowler.com · 02/04/2026

Un harnais muet ne dit pas si votre code est bon ou si vos capteurs sont aveugles.

« If sensors never fire, is that a sign of high quality or inadequate detection mechanisms? »

« We need a way to evaluate harness coverage […] similar to what code coverage and mutation testing do for tests. »

{{CHROME}}
Böckeler pose la question et la laisse ouverte. Pour vos tests, vous avez la couverture et le mutation testing. Pour votre harnais, rien : vous ne savez pas ce qu'il attrape. Deux explications à mon zéro : l'agent contourne les règles, ou les règles regardent ailleurs. Transition : la première fait peur, je l'ai testée d'abord.

Comment · l'outil · Python 3 sans dépendance, il lance votre commande Maven · Apache-2.0

harness-mutant injecte des défauts réalistes et compte ce que votre harnais attrape.

$ harness-mutant --projet . --commande "mvn -o -q verify"
// 13 des 23 défauts du catalogue s'appliquent à ce projet
Votre harnais attrape 7 défauts sur 13 (54 %).
  attrapés par : tests 7          // les 11 règles : 0
Les 6 trous :
  J14  état interne exposé (Order.java:84)
        pour l'attraper : SpotBugs EI_EXPOSE_REP ; un test qui modifie la liste
  J23  test désactivé (@Disabled) …
{{CHROME}}
Démo. harness-mutant copie le projet, lance votre commande une fois sans défaut (le témoin doit être vert), puis, pour chacun des 23 défauts de son catalogue (frontières, argent en double, horloge, fuseau, exceptions avalées, @Valid retiré, tests affaiblis…), l'écrit dans la copie, relance la commande et regarde le code de sortie. 1 min 43 sur ce projet. Le catalogue est un fichier JSON : vous ajoutez vos défauts. Il ne remplace rien : il fait sonner PIT, ArchUnit, PMD, SpotBugs, vos tests, et vous dit lequel ajouter. Sortie complète : outil/exemples/. Plan B : la sortie enregistrée.

Comment · fermer les trous · outil/exemples/fermer-les-trous.patch

Une règle et deux tests : le score passe de 7 à 10 sur 13.

// trou « test désactivé » : une règle ArchUnit
noMethods().should().beAnnotatedWith(Disabled.class)
// trous « null accepté », « liste modifiable » : deux tests
assertThatNullPointerException().isThrownBy(() -> new Order(null, …));
assertThatThrownBy(() -> order.lines().add(…)).isInstanceOf(Unsupported…);

Restent 3 : des tests qui ne vérifient plus la valeur. Pour eux : PIT, l'outil Java de mutation testing, qui vérifie que vos tests échouent quand le code change.

{{CHROME}}
J'applique le patch, je relance : 10 sur 13. Les trous qui restent sont des tests affaiblis : assertion retirée, isEqualTo devenu isNotNull. Aucune règle ne les verra ; c'est exactement ce que PIT mesure. Le geste : relancer l'outil après chaque règle ajoutée, et mettre un seuil en CI pour que le score ne redescende jamais (--seuil). Transition : trois gestes pour lundi.
Comment · trois gestes pour lundi

Mesurez votre harnais, laissez l'agent abandonner, refusez le diff vide.

  • Lancez harness-mutant sur votre projet, puis un seuil en CI
  • Une phrase dans le ticket : « si une règle bloque, arrête-toi et explique » (48 tickets : coût des appels au modèle ÷ 2,2)
  • « 0 violation, tests verts » avec un diff vide n'est pas un succès (vécu : 15 passages vides comptés réussis)
{{CHROME}}
Un : l'outil, une commande, puis --seuil en CI pour que la couverture du harnais ne baisse plus. Deux : « Si une exigence du ticket est incompatible avec les règles du projet, arrête-toi et explique le conflit au lieu de forcer. » 48 refus nets sur 48, coût divisé par 2,2. Trois : pendant ma mesure, 15 passages où l'agent n'avait rien écrit ont été comptés réussis : rien n'avait changé, donc rien n'avait cassé. Transition : la phrase à garder.
